# Academia Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Academia, a multi-user IB grade tracker (MYP + DP) with goals, analytics, a ManageBac-linked calendar, ⌘K search, a public SEO/GEO landing site and database-enforced privacy.

**Architecture:** Next.js App Router on Vercel. Server Components read through a Supabase server client carrying the user's JWT, so Postgres RLS applies to every query. Writes are zod-validated Server Actions. The grade engine is pure TypeScript shared by every screen.

**Tech Stack:** Next.js (latest) · React 19 · TypeScript strict · Tailwind v4 · shadcn/ui · Supabase (@supabase/ssr) · Recharts · lucide-react · next-themes · zod · date-fns · ical.js · three/@react-three/fiber/@react-three/drei · Vitest · HyperFrames (hero film).

**Spec:** `docs/superpowers/specs/2026-10-30-academia-design.md`

## Global Constraints

- Colours (light): bg `#FAFAF8`, bg-2 `#F3F4F6`, text `#171717`, text-2 `#737373`, accent `#4F46E5`, accent-2 `#A5B4FC`, success `#10B981`, warning `#F59E0B`, decline `#EF6461`, border `#E5E7EB`.
- Colours (dark): bg `#101114`, bg-2 `#1A1B1F`, card `#222329`, text `#F5F5F5`, text-2 `#A1A1AA`, accent `#818CF8`, border `#303137`.
- Fonts: Inter (UI/body), Plus Jakarta Sans (display headings), JetBrains Mono (all numbers, `tabular-nums`).
- Radius: cards 12px; buttons and inputs 8px. Spacing on an 8px grid. Icons: lucide-react only. Charts: Recharts only.
- Theme modes: light (default), dark, system.
- MYP boundaries: 1–5→1, 6–9→2, 10–14→3, 15–18→4, 19–23→5, 24–27→6, 28–32→7. Criteria A–D, each 0–8.
- DP default boundaries (editable per subject): 7≥80, 6≥70, 5≥60, 4≥50, 3≥40, 2≥30, 1≥0 (percent).
- Estimated grades are always labelled "Estimated"; school grades "Reported", with a different badge style and icon.
- No Supabase service-role key anywhere in the app. Every table has RLS owner policies.
- ManageBac feed fetch: https only, host ends with `.managebac.com` or `.managebac.cn`, 10 s timeout, 2 MB limit, no cross-host redirects.
- Password minimum length 10. Auth redirect `next` accepts only same-origin relative paths.
- Every animation honours `prefers-reduced-motion`; colour is never the only signal.
- Site URL comes from `NEXT_PUBLIC_SITE_URL` (default `https://academia-ib.vercel.app`).

## Review Focus

1. **MYP subject with only some criteria assessed** (e.g. only A and C): grade projects from the criteria present and shows "based on 2 of 4 criteria". Missing criteria never count as 0. *(Task 2 test `projects partial criteria`)*
2. **DP subject with graded work but no components defined**: falls back to weighting assessments by their own weight (default 1). It never shows "no grade". *(Task 2 test `dp without components`)*
3. **Pasted feed link variants** (`webcal://`, surrounding spaces, `http://`, look-alike hosts such as `managebac.com.evil.io`): normalised or rejected with a clear message. *(Task 9 validator tests)*
4. **Repeated ManageBac syncs**: they update existing rows by `external_uid` and never duplicate events or assessments. *(Task 9 test `upsert keys are stable`)*
5. **All-day ManageBac deadlines**: a `VALUE=DATE` deadline stays on the same calendar day in every timezone (stored as a date, not a UTC midnight). *(Task 9 test `all-day stays date-only`)*

  ```ts
  type Programme = 'MYP' | 'DP'; type Criterion = 'A' | 'B' | 'C' | 'D'
  type Aggregation = 'average' | 'latest' | 'highest' | 'median'
  interface EngineAssessment { id: string; date: string /* yyyy-mm-dd */; status: 'upcoming' | 'graded'; counts: boolean;
    criteria?: Partial<Record<Criterion, number | null>> | null; rawScore?: number | null; maxScore?: number | null;
    weight?: number | null; componentId?: string | null }
  interface EngineComponent { id: string; name: string; weight: number }
  interface Boundary { grade: number; min: number }
  interface SubjectConfig { programme: Programme; aggregation: Aggregation; components: EngineComponent[]; boundaries: Boundary[] }
  interface GradeResult { grade: number | null; percentage: number | null; criteria: Record<Criterion, number | null> | null;
    criteriaTotal: number | null; partial: boolean; criteriaUsed: number; basedOn: number }
  const MYP_BOUNDARIES: Boundary[]; const DEFAULT_DP_BOUNDARIES: Boundary[]
  mypGradeFromTotal(total: number): number
  percentToGrade(pct: number, boundaries: Boundary[]): number
  aggregate(levels: number[] /* chronological */, method: Aggregation): number | null
  computeSubjectGrade(list: EngineAssessment[], config: SubjectConfig): GradeResult
  gradeHistory(list: EngineAssessment[], config: SubjectConfig): { date: string; grade: number; percentage: number | null; assessmentId: string }[]
  trendOf(history: { grade: number }[]): { delta: number; direction: 'up' | 'down' | 'flat' }
  requiredForTarget(list: EngineAssessment[], config: SubjectConfig, target: number, next: { weight?: number; componentId?: string | null }):
    { required: number | null; achievable: boolean; unit: 'percent' | 'level' }
  ```
